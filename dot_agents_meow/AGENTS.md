# 代理指令维护规范（harness.SOUL.md 与 harness.AGENTS.md）

本目录的两份常驻指令文件，`harness.SOUL.md` 管人设，`harness.AGENTS.md` 管工程准则。本文件是改它们的维护规范；各节的理由、否决方案与出处在同目录的决策档案，改哪一节先读档案的哪一节，避免重开已经决议过的话题。

本文件占标准名，会被当成子目录规则注入：Pi 的 `pi-subdir-agents-md` 扩展与 opencode 在代理访问本目录路径时整份注入，dsh 只收集 git 根到 cwd 的链，不注入。三端的系统提示词模板都不引用本文件，所以这里只放每次编辑都要用的东西。

## 维护规范

- 两份文件都是**常驻系统提示词**，注入方式见“部署与边界”。
  每个 token 都常年占用模型的注意力预算。人设按锚点向维护：名字、称呼与选定锚点全部压成判据句与动机锚，素材只以行为锚形态内嵌，不铺陈清单，不设字数预算；
  工程规则按同一预算纪律精简。人设类内容归 `harness.SOUL.md`，工程规则归 `harness.AGENTS.md`，不交叉。
- 本文件与决策档案都是**活文档**：只记录当前有效的状态，更新时在原地重写对应小节，不追加带日期的流水账条目；变更历史由 git log 兜底（对应主文件“内容怎么改·不留旧账”条）。
- 日期只允许出现在“原则索引”表的更新日期列；正文、小节标题、小节内部都不放日期，文献的出版、发表年份是出处信息，不在此限。
- 理论出处、否决方案、维护信号按主题就近归档在决策档案的各自小节；跨小节的外部证据集中放在档案的“全局元发现”。
- 更新日期列记录该节规则最后一次实质变更的时间；纯粹的重构和措辞微调不改这一列。
- **措辞强度**：主文件的规则语气已按主人裁决整体放松（白话化重写），禁令与强断言改为平实但明确的表述。早期支持强断言的证据、以及行为回退时的恢复杠杆，备案在决策档案的“信息与工具调用”一节。
- **提示词内容不提文件名**：文件名与前缀是分发层细节，代理读到的永远是拼合后的正文，内容可能不经文件直接注入提示词。
  两份提示词的正文不引用 `harness.` 前缀与任何文件名；对外部文件类型的概念性引用不受限，如项目 `AGENTS.md` 的写法规范、`writing-for-agents` 技能的用途描述。
  本文件与决策档案以这些文件为讨论对象，不受限。

节分流表，加新规则时按对象归节；人设类，即名字、称呼与选定锚点，归 `harness.SOUL.md`，不进本表；对外署名整条随人设走 `harness.SOUL.md`；其余行为约束归 `harness.AGENTS.md`：

## 部署与边界

- 文件清单与加载方式：`harness.SOUL.md` 是人设，`harness.AGENTS.md` 是工程准则；opencode 与 Pi 在模板里依序 include 两份，dsh 的 `~/.dsh/AGENTS.md` 同收两份，三端注入序都是人设在前。
  `AGENTS.md` 是本文件，不被任何模板引用，不含行为规则；两份提示词与 `scripts/` 都由 chezmoi 分发到 `~/.agents_meow/`。
- 防串名前缀：`harness.` 只标三端常驻提示词文件。本文件占标准名是有意为之，它就是在本目录干活要守的规矩，注入即送达。
- 技能依赖方向：dotfiles 依赖 workflow-skills，反向不成立。workflow-skills 是公开仓，按 npx 分发；dotfiles 只声明技能名与来源，不 vendored。
  清单与安装态的一致性靠人眼对齐，校验体系已退役，理由见决策档案“工作流技能”。
- 结构：`harness.SOUL.md` 留锚点向常驻人设（约 30 行：分点锚、动机锚四条、语感样例四段短版），素材只以行为锚与判据句形态内嵌，不设独立素材清单；其余行为约束与产出物纪律归 `harness.AGENTS.md`。
  `harness.AGENTS.md` 以工程准则为主体：H1 开场后按四个决策域分组推进，元规则组的“规则优先级”打头；文末不留指回本文件的指针，托管与分发信息仍在本节。不引入第三份注入文件。
- 书写约定：主文件、本文件与决策档案提及具体技能一律带“技能”后缀，如 “`grilling` 技能”，消除与命令、文件名的身份歧义；仓库名与文档路径（workflow-skills、abstraction-design-references.md）不在其列。
