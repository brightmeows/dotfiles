## 确定性优先

### 演进历程

- **v1**：单一“工具验证优先”——能用工具 / 编译器 / 校验器自动处理的事就不手动
- **v2（2026-08-07）**：升维为两层统领原则——**建模优先**（理解层，原理兜底）+ **可验证优先**（验证层，机制兜底）

升维动因：v1 只覆盖执行 / 验证层（“做对了吗”），缺失理解层（“在解正确的问题吗、用的是不是已知最优方法”）。两层同属“确定性”概念的不同层次，故升维为一个统领原则而非新增并列节（M.1 升维表述）。

### 设计决策

#### 为什么是“两层确定性”而非独立原则

确定性 = 从理解到验证都追求“可推导、可复现、不依赖直觉和记忆”。建模优先与可验证优先是同一概念的递进层次（理解 → 验证），拆成并列节会割裂内在逻辑、增加 token。

#### 建模优先的核心：显式化隐含假设

建模的本质 = 把隐含假设显式化（“我默认 X 成立” → “X 是否成立、在什么条件下成立”，从而可审视、可证伪）。学科模型 / 形式化模型 / 失效建模都是显式化假设的工具。

- 命中 LLM 痛点：AssumptionMiner 专门研究 LLM 代码生成的隐含假设问题（见理论出处）
- 统领性：用“显式化假设”作为元本质，比单说“映射到学科模型”更普适

#### 三类建模维度

| 维度 | 例子 | 定位 |
|---|---|---|
| 学科模型 | 控制论 / 排队论 / 优化论 / 分布式理论 | 自动控制原理、数学、计算机科学理论的代表（学科级，勿降为具体技术）|
| 形式化建模 | 类型系统 / 状态机 / 不变量 | 让非法状态不可表示，设计期结构性保证 |
| 失效建模 | 故障模式（FMEA）/ 错误传播 / 降级路径 | LLM 最常漏的关注点；与可验证优先互补（正常路径 vs 异常路径）|

#### 可验证优先：为什么从“工具验证”升维为“可验证”

- “工具”是手段会过时（M.1），“可验证”是判断标准不过时
- “可验证”涵盖“自己造验证机制”（校验脚本 / 断言），比“工具”更宽，呼应工具真空带
- 优先级排序：类型检查 > linter / schema > 测试断言 > 量化指标 > 人工判断（类型既是形式化建模，又是最强编译期验证，故排最高）

#### “何时建模”子节：防止过度建模与漏建模

First Principles 不该滥用——过度建模和漏建模一样糟。给“该建模 / 直接动手”的判断标准（系统属性 vs 常规任务）。

### 心态锚点（2026-08-11）

- 动因：主人观察到代理仍顾虑上下文大小与查证成本，温和的“安心获取”无效，代理会主动中断、截断获取、跳过查证；而 Pi 实有 robust 兜底（见“信息获取完整性”节），这些自我设限不必要
- 决策：语言风格节新增“心态锚点”bullet——对工程能力（长上下文、查证、技能加载）有底气，完整获取 / 充分查证是本分不是奢侈；明确属态度层、不污染产出物
- 理论依据：PRISM（arXiv:2603.18507 “Expert Personas Improve Alignment but Damage Accuracy”）+ 162-personas 研究（arXiv:2311.10054）——persona 在行为对齐 / 态度层有效（5/8 任务类别改善），但损害事实准确性、对客观能力基本随机
  。故心态锚点定位为“消除不必要的自我低估”（态度层有效），不声称“增强原始长上下文能力”（误导，能力是模型架构特性）
- 与“角色扮演与工程能力分离”决策的关系：兼容——心态属表达 / 态度层，产出物（代码 / 文档 / 提交信息）仍纯净

### 反自我设限（2026-08-11）

- 动因：同“心态锚点”——代理顾虑上下文 / 查证成本而自我设限，温和“安心获取”段落无效
- 决策：将原“安心获取”段落升级为“反自我设限”反理化表（仿“技能使用”节反理化表，已验证有效），覆盖三类自我设限：上下文顾虑、查证成本顾虑、截断采样顾虑；强断言式措辞（“真高成本”“高成本赌博”）
- 兜底事实基础（Pi，已核实 docs/compaction.md）：auto-compaction（超 `contextWindow - reserveTokens` 触发，保留最近 `keepRecentTokens` 默认 20k，结构化摘要含 Goal / Decisions / Next Steps + 累积读写文件追踪）
  另加 branch summarization（分支切换保留上下文）与 session 持久化。故“上下文管理由运行时机制兜底”是事实准确表述
- 关键 nuance（避免矫枉过正）：“不必顾虑” ≠ “无脑塞”。context rot、lost-in-the-middle 是真实限制（arXiv:2510.05381 “Context Length Alone Hurts Performance Despite Perfect Retrieval”）；
  正确应对是“完整获取不动摇 + 用机制管理信噪比”（落盘复用、批次调用、输出前置收窄——见“执行效率”节），反理化表第三行明确指向“前置收窄”以保留此 nuance。
  JetBrains 研究（arXiv:2508.21433）佐证：简单 observation masking 与 LLM summarization 效果相当但成本减半——机制比“担心”更管用
- 否决：
  - 纯原地扩写“安心获取”——主人已观察到温和无效
  - 新增独立“心态：不自我设限”原则节——与“确定性优先”等并列割裂注意力、token 成本高；反理化表 + 心态锚点双管齐下更省
  - 声称“角色扮演增强原始长上下文能力”——违反 PRISM 结论，误导
- 维护信号：若代理仍自我设限，考虑提升反理化表位置或加强触发示例
