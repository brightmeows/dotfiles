## 主文件精简重构与技能移除（2026-09-10）

### 动因

- 主人要求：优化主文件与技能的表达，用更简单直接的方式增强遵循度；同时删除 humanizing-text 技能。
- 验收口径（经盘问确认）：规则语义无丢失、行数与字节下降、门禁通过；150 到 175 行的目标为预算而非硬门槛，冲突时规则完整优先。
- 范围：主文件与 humanizing-text 相关引用；skills 目录其余技能（grilling、querying-clippy-lints）不动。

### 决策

- 幅度：措辞精简 + 结构重排，含重复表述合并、阈值拆分、表格收束；不改规则语义、不加新规则。
- 结构：操作边界、技能使用前移至表达规范之后——两者原处注意力弱区（U 型曲线中部），分别是安全底线与任务首步行为（先查技能）；操作边界在前，按违反后果严重性排序。
- 拆分（阈值：并发约束超 3 或必须与建议混装）：协作方式·概念类比拆出 SQL 说明；可验证优先·工具真空带拆出校验器视角。
- 合并（重复表述只留一处）：安心获取段与反自我设限表去重；知识层级条目并入引导句；工作流三阶段标题降为粗体引导段；反合理化表触发行合并（6 行并 4 行，对策语义保留）；提交原则句并入段首；中文引号“严禁 / 检查”并段。

## 引言（角色提示）

### 第二人称身份指派（2026-08-13）

- 动因：主人问角色提示（标题 + 引言）可否优化，要求搜索互联网最佳实践；评估发现开头是第三人称文档式（“本文件是常驻工程工作准则”），身份声明只在标题，正文第一句（注意力最强位）被文档自我描述占据
- 决策：引言改“你是白喵斯的常驻工程助手。你的工作准则：……”，身份激活从文档描述变直接指派，长度不变，无 persona、无新增 token 负担
- 理论依据：
  - pecollective《System Prompt Design: 9 Patterns for Production LLMs (2026)》anatomy 模板：第一段即“Who is the model? What is its job?”，两到三句身份声明是生产级提示词标准构件
  - Anthropic 官方插件仓库 system-prompt-design.md（claude-plugins-official）：核心结构以“You are [specific role] specializing in [specific domain]”开头
  - 措辞研究已记结论：第二人称直接指令优于第三人称描述（Principled Instructions 原则 4 / 9）
  - primacy effect：开头注意力最强，宜放身份指派而非文档元描述
- 防守性评估（对照最佳实践后明确不加的东西）：
  - 不加 persona 性格——arXiv:2311.10054（2410 题 / 162 personas）与已记的 PRISM、Persistent Personas 同向，persona 不提升甚至降低表现
  - 不加长——Anthropic《The new rules of context engineering for Claude 5》(2026-07)：Claude Code 删 80% 系统提示词无编码评测损失，旧约束多为过时脚手架；本文件极简路线正合此向
  - 不“absurdly specific”化角色（buildmvpfast / pecollections 的具体化建议面向有界客服 bot 场景）；Anthropic 官方警示 overly specific roles 会限制 helpfulness，本文件是跨项目全局准则
- 否决：加 scope 边界句（Inflectra 的 scope layer 针对 bounded workflow 组件，本文件天然宽 scope）；角色句绑定领域（全局文件不能绑定特定领域）；全文第二人称化（已记否决：全面任务标记稀释权重）
- 维护信号：若模型仍把本文件当普通文档而非行为准则 → 考虑在优先级栈节加触发示例

## 确定性优先

### 演进历程

- **v1**：单一“工具验证优先”——能用工具 / 编译器 / 校验器自动处理的事就不手动
- **v2（2026-08-07）**：升维为两层统领原则——**建模优先**（理解层，原理兜底）+ **可验证优先**（验证层，机制兜底）
- **v3（2026-08-18）**：增第三层**单一事实来源**（存放层，权威源唯一）——理解、存放、验证三层闭环；决策见下文专项条目

升维动因：v1 只覆盖执行 / 验证层（“做对了吗”），缺失理解层（“在解正确的问题吗、用的是不是已知最优方法”）。两层同属“确定性”概念的不同层次，故升维为一个统领原则而非新增并列节（M.1 升维表述）。

### 设计决策

#### 为什么是“三层确定性”而非独立原则

确定性 = 从理解到验证都追求“可推导、可复现、不依赖直觉和记忆”。建模优先、单一事实来源与可验证优先是同一概念的递进层次（理解、存放、验证），拆成并列节会割裂内在逻辑、增加 token。（v2 时为两层，v3 增存放层后同理论延伸）

#### 建模优先的核心：显式化隐含假设

建模的本质 = 把隐含假设显式化（“我默认 X 成立” → “X 是否成立、在什么条件下成立”，从而可审视、可证伪）。学科模型 / 形式化模型 / 失效建模都是显式化假设的工具。

- 命中 LLM 痛点：AssumptionMiner 专门研究 LLM 代码生成的隐含假设问题（见理论出处）
- 统领性：用“显式化假设”作为元本质，比单说“映射到学科模型”更普适

#### 三类建模维度

| 维度 | 例子 | 定位 |
|---|---|---|
| 学科模型 | 控制论 / 排队论 / 优化论 / 分布式理论 | 自动控制原理、数学、计算机科学理论的代表（学科级，勿降为具体技术）|
| 形式化建模 | 类型系统 / 状态机 / 不变量 | 让非法状态不可表示，设计期结构性保证 |
| 失效建模 | 故障模式（FMEA）/ 错误传播 / 降级路径 | LLM 最常漏的关注点；与可验证优先互补（正常路径 vs 异常路径）|

#### 可验证优先：为什么从“工具验证”升维为“可验证”

- “工具”是手段会过时（M.1），“可验证”是判断标准不过时
- “可验证”涵盖“自己造验证机制”（校验脚本 / 断言），比“工具”更宽，呼应工具真空带
- 优先级排序：类型检查 > linter / schema > 测试断言 > 量化指标 > 人工判断（类型既是形式化建模，又是最强编译期验证，故排最高）

#### “何时建模”子节：防止过度建模与漏建模

First Principles 不该滥用——过度建模和漏建模一样糟。给“该建模 / 直接动手”的判断标准（系统属性 vs 常规任务）。

  - SSOT 定义：Wikipedia《Single source of truth》——每份数据只在一处 master（编辑），副本一律以引用存在；DRY 原文（Hunt & Thomas《The Pragmatic Programmer》）“每份知识必须有单一、无歧义、权威的表示”，且明确覆盖 schema、构建系统、文档
  - 形式化支撑：Zenodo《Formal Foundations for the Single Source of Truth Principle》
    (2026-01, doi:10.5281/zenodo.18182778，Lean 4 机器验证)——自由度 DOF=1（事实只在单一位置编码）是唯一保证编码一致性的表示；多处独立编码且值发散时真值原理上不可判定（Oracle Arbitrariness 定理），恢复一致的复杂度差距无界
  - 归属依据：真相不可判定即不可推导——与“确定性优先”哲学直接同源，故入本节而非独立成节
  - 漂移机理：IBM Think《Configuration Drift》(2026-04)、HashiCorp《Change Management At Scale》——漂移头号主因是带外修改（绕过权威路径直改运行态 / 产物）；对策三件套：变更走权威路径、漂移检测（对比实际与声明状态）、产物过期重建而非手补（不可变基础设施思想）
  - DRY 边界：Jacob Tan En (Medium, 2021)——“巧合相似”不等于同一知识，立即抽象属 hasty generalization，支撑“收敛有界”条
  - agent 场景：walkinglabs《Learn Harness Engineering》Lecture 03——仓库即 system of record，不在仓库里的信息对 agent 不存在；ericmjl《data-science-bootstrap-notes》——提交的配置文件是权威，本地与 CI 副本偏离即漂移（pre-commit parity）
- 否决：
  - 扩展“文档同步”节为“来源唯一与同步”——该节在具体行为区、方法论纯度低，泛化还要改节名，改动面大
  - 新顶层节——token 最贵，且有先例否决（“新增独立‘心态：不自我设限’原则节”决策：并列原则节割裂注意力）
  - 不加仅记 ref.md——gap 真实且三条均对应 agent 常见翻车点（手抄副本、直改产物、改源漏同步）
  - 精简两条版 / 单句版——主人选标准三条；“收敛有界”防过度抽象，值得占 token
- 维护信号：agent 仍手抄副本或带外直改产物时考虑加触发示例；以“单一事实来源”为名过度抽象时加强“收敛有界”
