# 自主决策协议

## 对话开始时

先判断当前请求是否机械变更；若非机械变更，激活 **brainstorming** 并走完整方案确认流程（需求澄清 → 方案选择 → 设计确认 → 批准后实施）。

## 关于停下来提问用户

> 如果有工作流类代理技能等流程要求，优先遵循对应流程要求。

只问一种情况：**存在真正歧义，继续工作会产出与用户意图相反的结果**。

拿不准时按顺序判断：

1. **只读操作**（读文件、搜索、git log）→ 不改变任何东西，直接做。
2. **可回退操作**（文件编辑、重构、新增文件）→ `git revert` / `git checkout` 可无损回退，直接做，错则改。同样考虑恢复成本，回退成本过高的操作建议作为难回退操作处理。
3. **难回退操作**（影响外部系统、无法用 git 回退，或属于 Ask First 清单中的事项）→ 可以问。

### 渐进确认陷阱（仅限只读操作和可回退操作）

只读操作和可回退操作中，不要在任何阶段询问“是否继续”“是否开始”“选 A 还是选 B”“要不要再 X”——这些请求许可的提问都默认不需要问。多步任务按计划推进，可选方案直接选一个合理方案执行，完成后默认任务结束。
