# 为代理写文档（Writing for Agents）

这是为任何**代理消费的文档**而写的参考：一份技能、一份 `AGENTS.md`（或 `CLAUDE.md`）、一篇被指针指到的文档。包装形式不同，写法相同：同一套杠杆让它们变得可预测，因为代理每次运行走的是同一个**过程**，而不是产出同一份输出。

当你写的是技能时，另读 [`SKILL-MECHANICS.md`](SKILL-MECHANICS.md)：那里讲 frontmatter、触发方式的选择与路由技能。

## 上下文指针（context pointer）

**上下文指针**是留在代理上下文里的一个引用：它指名某份上下文之外的材料，并编码“何时去取”的条件。技能的 `description` 是一个指针；`AGENTS.md` 里指向某文档的一行也是同一个物件。决定代理何时、多可靠地触达材料的，是指针的**措辞**，而不是它指向的目标。必需材料挂在措辞软弱的指针后面，是一个方差 bug：先把措辞磨利；磨不动，才考虑把材料内联。

指针干两件事：说明材料是什么，列出应当触发它的**分支（branches）**（分支是文档处理的一类不同情况，不同运行会走不同路径）。常驻指针的每个字每一轮都在花钱，所以它比正文更该被狠剪：

- **引导词放最前面**：指针是引导词发挥触发作用的地方。
- **一个分支一个触发条件**：给同一分支改名换姓的同义词，是一个分支写了两遍；合并它们，只留真正不同的分支。
- **删掉正文已经承担的身份说明**。

## 两种负载

你添加的每份文档与每个指针，都在花两种预算之一：

- **上下文负载（context load）**：常驻材料对代理窗口的开销，`AGENTS.md` 的一行、技能的 `description`，任何每轮都躺在上下文里的东西，无论是否触发都在消耗 token 与注意力。
- **认知负载（cognitive load）**：对人的开销，有哪些文档存在、何时该取哪一个。人就是索引。它不是要最小化的成本：这是人类能动性的代价；在需要人类判断的地方花它，不需要的地方去掉它。

只靠指针触达的材料逃掉上下文负载，代价是指针自己那一行；完全没有指针的材料，整个重量都压在认知负载上。

## 信息层级（information hierarchy）

文档由两类内容构成：**步骤（steps）**（代理按顺序执行的动作）与**参考（reference）**（按需查阅的定义、规则、事实）。两者自由混合：全步骤（一份配方）、全参考（一套评审规则、本技能），或两者兼有。核心决策是每块内容放在**信息层级**的哪一档，这是一架按“代理多迫切地需要该材料”排序的梯子：

1. **文件内步骤（in-file step）**是主档：代理要做什么，按顺序。
2. **文件内参考（in-file reference）**按需查阅。它常常是一组合理的平级内容（一套评审的每条规则都在同一档），这是正常安排，不是坏味道。
3. **披露出去的参考（disclosed reference）**被推入单独文件，由上下文指针触达，只在指针触发时加载。范围从同目录的兄弟文件，到任何位置、任何文档都能指向的外部参考。

推得太少，顶部膨胀；推得太多，隐藏了代理真正需要的材料。这一张力就是整个决策。

**渐进披露（progressive disclosure）**是把内容沿梯子下移（移出主文件、放到指针后面），让顶部保持可读。它主要不是 token 优化：这是保护层级本身的手段。分支是检验披露的最干净标准：每个分支都要用的内联，只有部分分支会碰的推到指针后面。当文档含步骤时，本该披露的文件内参考会埋掉步骤，让“关注步骤”变成抛硬币，这就不只是可读性问题，而是方差杠杆。

**就近组织（co-location）**是文件内的配套动作：梯子决定内容放多深，就近组织决定放定之后旁边放什么。一个概念的定义、规则与注意事项放在同一个标题下，不要四散，读一处就带出它的邻居。检验标准：文档读起来应像为代理写的文档；成组的内容读起来像，散落的不像。（它和重复不同：重复是把一个含义写在两处；散落是把一个含义碎在多处。）

**蔓延（sprawl）**是这一档的失效模式：文档就是太长，哪怕每一行都有效且唯一。注意力在过量中被摊薄，每一行额外内容都多一个需要保持相关的对象。解药还是梯子：把参考披露到指针后面，按分支或序列拆分，让每条路径只携带自己需要的东西。

## 步骤与完成判据

每个步骤都以**完成判据（completion criterion）**收尾：一个告诉代理“工作做完了”的条件。两条性质让它成为杠杆：

- **清晰度**：代理能否分辨“完成”与“未完成”？模糊的边界（“达成理解”）会招来**提前完成（premature completion）**：步骤还没真完成就收尾，注意力滑向“已经做完”。前面还看得见的步骤（**完成后步骤（post-completion steps）**）提供拉力，判据的清晰度是阻力。按顺序防守：**先磨利边界**（局部、便宜）；只有在边界确实无法更清晰、且你观察到冲刺时，才用拆分序列把后面的步骤藏起来。隐藏只在真实的上下文边界上起作用（交接或子代理派发）；内联调用会把后续步骤留在上下文里，什么都清不掉。
- **要求（demand）**：判据要多少工作量。“每个被改动的模型都已交代”会逼出彻底的工作，“产出一份变更清单”不会。要求驱动**铺垫工作量（legwork）**（代理在工作中做的挖掘，潜伏在措辞里，而不是写成独立步骤），而且它不限于步骤：“每条规则都已应用”约束一组平级参考，正如“每个步骤都完成”约束一个序列，一份全参考文档也能带着穷尽性门槛。

最强的判据既**可检验**又**穷尽**。

## 何时拆分

把一份文档拆成两份要花掉两种负载之一，所以只在拆分挣得回成本时才拆：

- **按序列拆**：一串步骤里，如果后续步骤会引诱代理催赶眼前这一步，就拆开。把它们挪出视野，能让当前任务获得更多铺垫工作量。小心反向操作：合并序列会让后续步骤暴露给当下的步骤，招来提前完成。
- **按触发方式拆**：技能专属，见 [`SKILL-MECHANICS.md`](SKILL-MECHANICS.md)。

## 引导词（leading words）

**引导词**是一个紧凑的概念，原本就活在模型的预训练里，代理执行文档时用它思考（_lesson_、_fog of war_、_tracer bullets_）。它以 token 的形式反复出现，从不作为句子出现，于是累积出一个分布式定义，用最少的 token 锚住一整片行为，靠的是调用模型已有的先验。自造词也行，前提是定义清楚；但自造词调不动先验：你用定义 token 买来的，是预训练里现成的词免费给你的东西。先找现成的词。

它锚两次。在正文里锚**执行**：词一出现，代理每次都会取同一套行为；在平级参考里，它把注意力聚焦到一类要找的东西上。在指针里锚**触发**：当同一个词活在你的提示词、文档与代码库里，代理会把这份共享语言与材料联系起来，更可靠地取到它。

主动寻找用引导词重构的机会：同一组意思在三处掰开写、一个指针用一整句去指一个想法，每一处都在请求收拢成一个 token：

- “快、确定、低开销”收成 _tight_（一条 _tight_ 循环）。
- “一个你信得过的循环”收成 _red_，把模糊门槛变成二值可观察状态（循环在 bug 上变 _red_，或者没变）。

你赢两次：token 更少，代理有了更锋利的挂钩来挂它的思考。假定每份文档都带着可以被引导词退休的复述，去找出来。

**否定式（negation）**是这个杠杆旁边的失效模式：用禁止来引导，会把被禁行为拖进上下文，反而让它的可及性更强，不是更弱。_别想大象_，结果满脑子都是大象；否定是一个弱修饰词，会被强烈激活的概念压过去，于是禁令有一半读起来像“去做那件事”的指令。要提示**正面**：说出目标行为（“注释只写一行”），被禁的那个就永远不会被说出口。禁令只在你无法正面表述的硬护栏处才配保留；即便如此，也要配上正面目标，让注意力落在该做的事上。

## 剪除（pruning）

- 每个含义只留**单一事实来源（single source of truth）**：一个权威位置，改行为就是改一处。**重复（duplication）**（同一含义出现在多于一处）付出维护与 token 成本，还会在层级上把该含义的显眼度抬过它真实的位置。（它是引导词的无意反面：引导词故意重复 token，绝不重复含义。）
- **环境**也是事实来源（`package.json` 的 scripts、配置文件、目录结构、`--help` 输出）；文档若复述它，就是一份**缓存（cache）**：拷贝一次查询结果，只有当那次查询昂贵时才配得上它的负载。缓存代理查不到的东西：没写下来的约定、某个选择背后的理由、没有任何配置会坦白的坑。把单文件、单命令就能查到的留给环境，放在那里它不会过期。
- 逐行检查**相关性**：这一行是否仍作用于文档所做的事？一行失去相关性，或者因为从不作用于任务（纯说明，或本应披露的分支），或者因为所描述的行为与世界变化而过期。更短的文档更容易保持相关。没有剪除纪律，默认命运是**沉积（sediment）**：各层过期内容沉积下来，因为加东西感觉安全、删东西感觉冒险，直到你必须一层层钻下去找还活着的东西。
- 逐句猎**无效指令（no-op）**：模型默认就遵守的指令，花了负载却什么都没说。检验（它相对默认行为改变了什么？）是相对模型而非相对读者的：两个人对无效指令的分歧，其实是对默认行为的分歧，靠跑文档解决，不靠辩论。一句话通不过，就整句删掉，而不是从里面抠字。这个检验也用来给引导词打分：弱到打不过默认的词（代理本来就“比较彻底”时写 _be thorough_）就是无效指令；改法是换更狠的词（_relentless_），不是换技术。
