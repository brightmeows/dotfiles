# Subagent 驱动执行

逐任务分发独立 subagent，每任务实施后经两轮审查：规范合规审查先行，代码质量审查随后。

**原理：** 将任务委托给具有隔离上下文的专用 subagent。通过精确构造指令和上下文，确保它们聚焦于任务并成功。Subagent 不继承当前会话的上下文或历史——你精确构造它们所需的信息。这同时也保留了协调工作的上下文。

**核心原则：** 每任务新 subagent + 两阶段审查（规范→质量）= 高质量、快速迭代。

**连续执行：** 不要在任务之间暂停询问用户。除非遇到无法解决的阻塞、真正阻碍进展的歧义、或所有任务完成，否则连续执行所有任务。用户让你执行计划，那就执行。

## 流程

### 准备

读取蓝图文档，提取所有任务的完整文本和上下文，创建 Todowrite。

### 每任务循环

对每个任务：

1. **分发实施 subagent**
   - 使用 `exec-implementer` subagent
   - 提供任务完整文本 + 上下文
   - Subagent 可先提问，回答后继续
   - 实施完成后返回状态

2. **分发规范审查 subagent**
   - 使用 `exec-compliance-reviewer` subagent
   - 核验实现是否与需求一致（不多不少）
   - 如有问题 → 实施 subagent 修复 → 重新审查
   - 通过后进入下一步

3. **分发代码质量审查 subagent**
   - 使用 `exec-quality-reviewer` subagent
   - 审查代码质量、测试覆盖、文件结构
   - 如有问题 → 实施 subagent 修复 → 重新审查
   - 通过后标记任务完成

### 完成

所有任务完成后，分发最终 `code-reviewer` 全面审查整个实现。

## 实施 subagent 状态处理

实施 subagent 返回四种状态之一：

**DONE：** 进入规范审查。

**DONE_WITH_CONCERNS：** 完成工作但有疑虑。先阅读疑虑再进入审查。如涉及正确性或范围，先处理再审查。

**NEEDS_CONTEXT：** 需要额外信息。提供后重新分发。

**BLOCKED：** 无法完成任务。评估阻塞原因：
1. 上下文不足 → 补充信息后重试
2. 任务需更强推理 → 换更强大的模型
3. 任务过大 → 拆分为更小单元
4. 计划本身有误 → 升级给用户

**切勿**忽略升级或强制相同模型无变化重试。

## 关键要点

- 切勿在 main/master 分支上直接开始实施
- 不跳过审查（规范审查和代码质量审查都需要）
- 不带着未修复的问题继续
- 不并行分发多个实施 subagent（会冲突）
- 不让 subagent 自己读计划文件（提供完整文本）
- 不跳过场景上下文（subagent 需要理解任务所处位置）
- 不忽略 subagent 的问题（先回答再让其继续）
- 规范审查发现的问题 = 没完成，需修复
- 审查发现问题 → 实施者修复 → 重新审查，不跳过循环
- 不先开始代码质量审查再通过规范审查（顺序不能错）
- 不在审查仍有未关闭问题时进入下一任务

## 模型选择建议

- **机械实施任务**（1-2 个文件、明确规格）：用快速便宜的模型
- **集成/判断任务**（多文件协调、调试）：用标准模型
- **架构/设计/审查任务**：用最强模型
