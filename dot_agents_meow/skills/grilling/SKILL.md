# 盘问（Grilling）

## 机制：设计树、轮次与前沿

像面试官一样持续盘问用户，直到双方达成共识。把整个过程映射为一棵**设计树（design tree）**：每个决策都会分叉出挂在它之下的子决策。

以**轮（rounds）**为单位推进这棵树。**前沿（frontier）**指所有前置条件已经敲定的决策——也就是你**现在**就能问的问题，不必猜测你还没听到的答案。一轮可以只问一个问题，也可以把若干前沿问题合并问，自行分组。给每个问题编号并附推荐答案，等用户答完一整轮再进入下一轮。同一轮的问题必须互相独立——有依赖时，被依赖的先问，依赖方留到更晚的轮次。

每一轮，用户的回答都会重塑这棵树——已敲定的决策把前沿向外推，解开依赖它们的后续问题。重新计算前沿，进入下一轮。

## 提问格式与编号纪律

每个问题都应按如下格式：

```
**Q1** - **<问题标题>**：<问题正文，可以是多段，包含多个选项>

**推荐答案**：<你的推荐答案>
```

推荐答案是必填项：确实没有明确倾向时，写“无倾向”并简述各选项利弊，禁止静默省略。

编号纪律：问题编号 Q1、Q2…全局连续递增，不跳号不复用；问题内多个选项统一用 A、B、C…编号，推荐答案引用时写“推荐 A：理由”；引用前置结论写“Q{m} 的结论”，不复述旧问题。

**推导决定（D 系列）**：从已敲定回答中逻辑推导出的结论——无需再问，但必须让用户知情。编号 D1、D2…与 Q 系列独立递增。D 在它产生的当轮立即随问题披露，列在问题之前，禁止攒到收尾才统一提出；格式：

```
**D1** - **<决定标题>**：<结论>（由 Q{m} 推导）
```

D 默认采纳，用户可指出异议；若被推翻，把推导链中未明说的前提升格为新的 Q 问题重新走查。

## 优先用结构化提问工具

若环境提供结构化提问工具（如 `questionnaire`、`question`），优先用它呈现整轮问题，不可用时回退纯文本。配套约定：

- **正文先行**：调用工具前，正文按上面的格式完整列出本轮的 D 与 Q（含每问推荐答案），工具只作点选入口。
- **选项带推荐提示**：选项的 description 里注明推荐标记与理由。

## 信息与决策分工

查**信息**是你的职责，绝不是用户的。这里的“信息”泛指一切需要获取的内容——既包括环境中的事实，也包括外部知识。当前沿问题需要这类信息时，自己去查清楚（按环境能力选用工具、子代理或并行探查）——凡是能自己查到的，都别去问用户。不要卡在它上面：一次进行中的探查是一个未敲定的前置条件，因此只有它下游的问题才要等探查完成——本轮先问前沿中不依赖探查的问题，依赖信息的留到探查完成后的下一轮再问。**决策**属于用户——逐条抛给他们，然后等待。

信息查清只解开下游问题的前置条件，不等于那些问题已被回答：依赖信息的决策若含用户偏好或取舍，仍要作为 Q 逐条问，禁止用查到的信息替用户敲定；只有纯粹由信息与已敲定决策推导的结论才可归为 D。

## 完成与收尾

当前沿为空时，会话才算结束：所有探查均已完成、依赖信息的下游 Q 均已问过，设计树的每个分支都已走查过，没有留下任何被默默假设的东西。此时停下，把已敲定的决策列成**按领域分组的清单**：每个主题分支一组，组内 Q 按编号排列，D 跟在它依赖的 Q 后面（D 已在当轮披露过，此处仅汇总）：

```
## <领域一>

- **Q1** - <结论>
- **D1** - <结论>（由 Q1 推导）
- **Q4** - <结论>

## <领域二>

- **Q2** - <结论>
- **Q3** - <结论>
```

收尾确认不可跳过——即便信息已查明、选项看似唯一，也须把清单交用户确认。请用户确认共识，并让用户选择下一步：开始实施 / 继续盘问 / 调整决策。用户做出选择前，不要基于共识采取行动。
