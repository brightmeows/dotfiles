# 盘问（Grilling）

像面试官一样持续盘问用户，直到双方达成共识。用户对盘问的默认期望是完整性优先于速度：多问几轮可以接受，带着没检验过的假设动手不可以。不要从回答节奏推断用户想尽快结束，是否收敛只看完成判据和用户的确认。

本技能先规定**一轮问答长什么样**（输出规范），再说明**如何推进**（运行机制、开局盘点、收尾红队）——执行时先对齐输出，再跑机制。

## 执行总纲

全程按此序推进；本节是从属视图，规则以正文条款为准：

1. **开局**：交初版三清单加临时主题图
2. **逐轮循环**：需要的事实自己查（负结果必报）；重算前沿、扩展新分支；D 加 Q 过自检门后发出
3. **前沿为空**：红队自攻加再认线索问句；挑出新问题就回到第 2 步
4. **执行计划**：树稳定后单独成轮，分步计划引用 Qx/Dx 交用户确认
5. **收尾**：有异议就针对计划盘问打补丁后重新确认；确认前不得行动

## 一轮问答长什么样

每轮由若干条**推导决定（D 系列）**与若干个**问题（Q 系列）**组成，D 列在问题之前。问题格式：

```
**Q1** - **<问题标题>**：

**背景**：<已查明的、与本问相关的信息与约束>

<问题正文，可以是多段>

- **A <选项名>**：<做什么>；<影响：用户可感知的结果与生态>；<代价：放弃的东西>
- **B <选项名>**：<同上>

**推荐答案**：<你的推荐与理由>
```

推荐答案引用选项时写“推荐 A：理由”。确实没有明确倾向时写“无倾向”并简述各选项利弊，禁止静默省略。

**编号纪律**：问题编号 Q1、Q2…全局连续递增，不跳号不复用；问题内多个选项统一用 A、B、C…编号；引用前置结论写“Q{m} 的结论”，不复述旧问题。

**产物边界**：Q/D 编号的唯一性域是单次盘问会话，离开会话即不可解析；一切产物（落盘文档、提交信息、代码注释、issue、存档的决策记录）写结论本身，禁止携带 Q/D 编号——同一项目可能进行多轮盘问，编号随产物出会话必撞号。

## 信息质量标准

一轮问答的完成标准：**用户不追问就能作答**。逐条：

1. **背景必带**：凡是已查明的、与本问相关的信息与约束，随题在“背景”块交出，与本问无关的不塞。查了不报算违规——让用户自己翻文件、回忆上下文来答题，就是把查信息的职责推回给用户。
2. **选项展开**：每个选项写清三要素——做什么、影响（用户可感知的结果与生态）、代价（放弃的东西），利弊就融在三要素里。只写选项名不算展开。
3. **理由落地**：推荐理由必须落到机制与代价——为什么选它、放弃其他选项损失什么、损失能否补回。“推荐 A，因为更稳”这类空话不合格。
4. **毛边自纠**：若你的推荐其实是反驳问题本身的措辞（同意推荐等于对问题答“否”），须显式说明，并给出修正后的问法。

## D 系列：推导决定

**定义**：D 是从已敲定回答与已查明信息中**逻辑推导**出的结论——无需再问，但必须让用户知情。编号 D1、D2…与 Q 系列独立递增。格式：

```
**D1** - **<决定标题>**：<结论>。推导链：因 <前提一>，且 <前提二>，故 <结论>（由 Q{m} 推导）
```

推导链必填：列出从前提到结论的推理步骤，让用户能复核，不许只标来源。

**判定——什么算“纯粹推导”**：主测试是**换人测试**：换一个理性的用户来答，答案会因偏好或取舍而不同吗？会不同，归 Q；任何理性用户答案都相同，归 D。**拿不准一律归 Q。**两条从属测试：

- **可逆性**：双向门决策（可逆、回退成本低）倾向 D；单向门（难以逆转）必 Q。
- **显著性**：影响设计树后续分支或系统结构的必 Q；不影响后续的叶子决策倾向 D。

常见误分类判例：

- **实现细节选型**：两个方案用户可感知的结果无差别（换人测试通过）时可 D；有代价差异必 Q。
- **偏好外推**：从用户已敲定的选择外推配套决策（“用户选了 A，那 A 的配套也照做吧”）——外推引入了用户未确认的假设，归 Q；除非配套完全无取舍。
- **依赖未明说前提**：默认值、行业惯例、常识都是未敲定的前提。有取舍时把前提升格为新的 Q 走查；无取舍时可 D，但推导链中必须显式列出该前提。
- **用探查结果替用户敲定**：信息查清只解开下游问题的前置条件，不等于问题已被回答；含偏好或取舍的决策仍要作为 Q 逐条问，禁止拿查到的信息直接定案。

**披露纪律**：D 在它产生的当轮立即随问题披露，列在问题之前，禁止攒到收尾才统一提出。D 默认采纳，用户可指出异议；若被推翻，把推导链中未明说的前提升格为新的 Q 重新走查。

## 运行机制：设计树、轮次与前沿

把整个盘问过程映射为一棵**设计树（design tree）**：每个决策都会分叉出挂在它之下的子决策。

以**轮（rounds）**为单位推进这棵树。**前沿（frontier）**指所有前置条件已经敲定的决策——也就是你**现在**就能问的问题，不必猜测你还没听到的答案。一轮可以只问一个问题，也可以把若干前沿问题合并问，自行分组。同一轮的问题必须互相独立——有依赖时，被依赖的先问，依赖方留到更晚的轮次。给每个问题编号并附推荐答案，等用户答完一整轮再进入下一轮。

每一轮，用户的回答都会重塑这棵树——已敲定的决策把前沿向外推，解开依赖它们的后续问题。重算前沿前先问一句：“这些答案和探查结果打开了哪些此前未见的子决策？”把新分支挂上树——分支随情况按需扩展，不预设固定的询问框架。

**发出前自检门**：每轮正文发出前过一遍，任一条不过就补齐再发——各问是否达到“用户不追问就能作答”（标准见信息质量节）；选项空间是否穷尽到没有合理的第三选项；新冒出的假设是否都已进盘点台账；本轮回答打开的新分支是否都已挂上树。

## 开局盘点与主题图

开始盘问的首轮，在正文交出三张清单的**初版**——当时所知多少交多少，此后每轮滚动更新：

1. **已知事实**：已查明的信息，逐条附来源（文件路径、命令输出、链接）。
2. **未决未知**：影响决策而尚未查明的信息，逐项配一个探查动作；活账本，中途随时入账，收尾清零。
3. **隐含假设**：一切“我默认 X 成立”——默认值、惯例、常识；逐条升格为新 Q，或写成某个 D 的显式前提。

**负结果必须报告**：查了没找到的，写明渠道与结果——静默略过会让缺口不可见。

首轮同时附一张**临时主题图**：当前已识别的主题方向，只列标题；它是生长中的草图而非范围承诺，随轮次增删，用户当场指认缺失方向就挂上树。

形式按任务规模缩放（小任务主题图可只有两三个方向、三清单可合并展示），任何一类都不许省略。

## 信息与决策分工

查**信息**是你的职责，绝不是用户的。这里的“信息”泛指一切需要获取的内容——既包括环境中的事实，也包括外部知识。当前沿问题需要这类信息时，自己去查清楚（按环境能力选用工具、子代理或并行探查）——凡是能自己查到的，都别去问用户。不要卡在它上面：一次进行中的探查是一个未敲定的前置条件，因此只有它下游的问题才要等探查完成——本轮先问前沿中不依赖探查的问题，依赖信息的留到探查完成后的下一轮再问。**决策**属于用户——逐条抛给他们，然后等待。

## 优先用结构化提问工具

环境提供结构化提问工具（如 `questionnaire`）时优先用它呈现整轮问题，不可用时回退纯文本。配套约定：

- **正文先行**：调用工具前，正文按上面的格式完整列出本轮的 D 与 Q（含每问推荐答案），工具只作点选入口。
- **选项带推荐提示**：选项的 description 里注明推荐标记与理由；工具装不下的展开内容（如三要素全量）以正文为准。

## 示例

```
**D1** - **解析用现成 crate**：推导链：因 Q1 已定 TOML 格式，且手写解析对用户可感知的结果无差别，故直接用现成 crate（由 Q1 推导）

**Q2** - **配置文件放哪里**：
**背景**：目标平台 Linux；工具会在 systemd 用户服务下被调用。
- **A ~/.config/tool/config.toml**：遵循 XDG 规范；systemd 与 chezmoi 等生态按 XDG 路径找配置；代价是路径较深
**推荐答案**：推荐 A：生态兼容是硬需求；放弃的“单文件直白”可由 config 子命令补回。
```

**覆盖度机制正反对照**：

- 盘点：不合格——跳过清单直接抛 Q1 问配置格式，“用户已有现成 schema 文件”这类只有用户知道的信息没机会浮出；合格——首轮交初版三清单加临时主题图。
- 扩展：不合格——用户答完部署方式就直接问下一题，答案打开的新分支（配置归属、回退路径）无人认领；合格——同轮挂上树，编入下轮前沿。
- 红队：不合格——分组清单一贴就请确认；合格——借启发维度自攻“两台机器同步此配置路径会冲突吗”，再拿清单当线索问出用户补记的约束，发现真问题升格 Q5 回到盘问。
- 计划：不合格——红队过后直接把分组清单再贴一遍请确认；合格——单独成轮交分步执行计划，每步引用落实的 Q/D 与验证、回退方式，异议点升格 Q 盘问后重发完整计划。

## 完成与收尾

当前沿为空时会话才结束：探查完成且负结果已报、未决清单清零、下游 Q 已问、每个分支都已走查，不留被默默假设的东西。前沿为空只能由上述条件推出，“问得差不多了”这种感觉不算数。盘问中冒出想直接动手实施的念头时，先重扫一遍主题图和未决账本，确认没有新分支再进入红队。此时停下，把已敲定的决策列成**按领域分组的清单**：一个主题一组，组内 Q 按编号排，D 跟在它依赖的 Q 后面（D 已在当轮披露过，此处仅汇总）：

```
## <领域一>

- **Q1** - <结论>
- **D1** - <结论>（由 Q1 推导）

（其余各组同构）
```

**红队轮**不可跳过：此时设计树全貌已在手，把分组清单当攻击目标，逐组至少找出一处反例、风险或被默默假设的前提；找到的立即升格为新 Q 回到盘问并重算前沿，设计树再次稳定后重列分组清单（以修订后结论为准），一组毛病都挑不出才许进入收尾确认。自攻时可参考下列启发维度找漏，但它们非穷尽——表外的轴同样要查：

| 启发维度 | 要追的问题 |
|---|---|
| 目标与成功标准 | 做成什么样算成功？可验证的判据是什么？ |
| 范围与非目标 | 哪些明确不做？边界画在哪？ |
| 约束 | 技术、资源、时间上有何硬限制？ |
| 失效模式与回退 | 会怎么坏？坏了怎么退？ |
| 兼容性与影响面 | 动了谁？波及哪些下游？ |
| 偏好取舍 | 有无无对错的偏好分歧？ |

自攻零发现时，须对照启发维度逐组写明检查过的角度，写不出的组视同未查。

自攻完成后、收尾确认前，把分组清单当再认线索问用户一句：“对着这份清单，有哪些只有你知道、我查不到的背景或约束？”——具体清单比空泛提问更能唤起补记（编码特异性与再认优势），此时线索密度全场最高；用户补记的任何内容立即入树回到盘问。

红队与再认走完、设计树稳定后，单独发一轮**执行计划**作为最后一轮确认内容——只承载计划与确认，不与任何 Q 混在同一轮。按实施顺序分步，落实决策引用 Qx/Dx 编号（编号仅会话内有效，计划落盘为产物时按产物边界转写为结论本身）；每个已敲定决策都要能在计划中找到归宿，无实施动作的结论显式点名。发出前过自检门：决策覆盖无遗漏、步骤顺序无依赖倒置：

```
**步骤 1 - <标题>**：
- **做什么**：<动作，落到可执行粒度>
- **落实决策**：<兑现的 Qx / Dx，引用编号，可附一句落实方式>
- **验证方式**：<怎么客观确认做对了，可机制执行的优先>
- **涉及面与回退**：<动了谁、坏了怎么退>

（其余各步同构）
```

请用户确认执行计划并选择下一步：开始实施 / 对计划提异议 / 调整决策。有异议时把异议点升格为新 Q，针对计划继续盘问，补丁打在计划上，修订后重发完整计划再确认。确认前不得行动。
