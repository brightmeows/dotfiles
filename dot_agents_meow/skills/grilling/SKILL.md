# 盘问（Grilling）

像面试官一样持续盘问用户，直到双方达成共识。用户对盘问的默认期望是完整性优先于速度：多问几轮可以接受，带着没检验过的假设动手不可以。不要从回答节奏推断用户想尽快结束，是否收敛只看完成判据和用户的确认。

本技能先规定**一轮问答长什么样**（输出规范），再说明**如何推进**（运行机制、开局盘点、收尾红队）——执行时先对齐输出，再跑机制。

## 执行总纲

全程按此序推进；本节是从属视图，规则以正文条款为准：

1. **开局**：交初版三清单加临时主题图
2. **逐轮循环**：需要的事实自己查（负结果必报）；重算前沿、扩展新分支；问题过自检门后发出
3. **前沿为空**：进入红队（自扮攻击者找方案漏洞），加记忆线索问句；挑出新问题就回到第 2 步
4. **执行计划**：树稳定后单独成轮，分步计划引用 问题N 交用户确认
5. **收尾**：有异议就针对计划盘问打补丁后重新确认；确认前不得行动

## 一轮问答长什么样

每轮由若干个**问题**组成。问题格式：

```
**问题1** - **<问题标题>**：

**背景**：<已查明的、与本问相关的信息与约束>

<问题正文，可以是多段>

- **A <选项名>**：<做什么>；<影响：用户可感知的结果与生态>；<代价：放弃的东西>
- **B <选项名>**：<同上>

**推荐答案**：<你的推荐与理由>
```

推荐答案引用选项时写“推荐 A：理由”。确实没有明确倾向时写“无倾向”并简述各选项利弊，禁止静默省略。

**编号纪律**：编号 问题1、问题2…全局连续递增，不跳号不复用；问题内多个选项统一用 A、B、C…编号；引用前置结论写“问题{m} 的结论”，不复述旧问题。

**产物边界**：问题编号的唯一性域是单次盘问会话，离开会话即不可解析；一切产物（落盘文档、提交信息、代码注释、issue、存档的决策记录）写结论本身，禁止携带问题编号——同一项目可能进行多轮盘问，编号随产物出会话必撞号。

## 信息质量标准

一轮问答的完成标准：**用户不追问就能作答**。逐条：

1. **背景必带**：凡是已查明的、与本问相关的信息与约束，随题在“背景”块交出，与本问无关的不塞。查了不报算违规——让用户自己翻文件、回忆上下文来答题，就是把查信息的职责推回给用户。
2. **选项展开**：每个选项写清三要素——做什么、影响（用户可感知的结果与生态）、代价（放弃的东西），利弊就融在三要素里。只写选项名不算展开。
3. **理由落地**：推荐理由必须落到机制与代价——为什么选它、放弃其他选项损失什么、损失能否补回。“推荐 A，因为更稳”这类空话不合格。
4. **措辞偏差自纠**：若你的推荐其实是反驳问题本身的措辞（同意推荐等于对问题答“否”），须显式说明，并给出修正后的问法。

## 推导结论也编为问题

从已敲定回答与已查明信息中**逻辑推导**出的结论，同样编为问题交用户确认——没有“无需再问”的类别，每个结论都要用户显式点头，沉默不视为确认。推导过程写进“背景”块：因 <前提一>，且 <前提二>，故 <结论>（由 问题{m} 推得），列出推理步骤供复核，不许只标来源；选项给出该结论与可行替代（或“确认 / 异议”），推荐答案照常标注；确认型问题的选项三要素可塌缩——确认项写采纳该结论的影响与代价，异议项写指出哪条前提不成立。用户答“否”时，把推导链中未明说的前提升格为新问题重新走查。

推导结论在其前提敲定后、组构下一轮时立即编入，禁止攒到收尾才统一确认，也不得塞进已发出的轮次。

**禁止当作已敲定的四种情形**（都须作为问题走查）：

- **实现细节选型**：两个方案用户可感知的结果无差别也要问（作为确认型问题编入下一轮）；有代价差异更必问。
- **偏好外推**：从用户已敲定的选择外推配套决策（“用户选了 A，那 A 的配套也照做吧”）——外推引入了用户未确认的假设，配套取舍单独成问。
- **依赖未明说前提**：默认值、行业惯例、常识都是未敲定的前提；有取舍就升格为新问题，无取舍也不例外，且背景中必须显式列出该前提。
- **用探查结果替用户敲定**：信息查清只解开下游问题的前置条件，不等于问题已被回答；含偏好或取舍的决策仍要逐条问，禁止拿查到的信息直接定案。

## 运行机制：设计树、轮次与前沿

把整个盘问过程映射为一棵**设计树（design tree）**：每个决策都会分叉出挂在它之下的子决策。

以**轮（rounds）**为单位推进这棵树。**前沿（frontier）**指所有前置条件已经敲定的决策——也就是你**现在**就能问的问题，不必猜测你还没听到的答案。一轮可以只问一个问题，也可以把若干前沿问题合并问，自行分组。同一轮的问题必须互相独立——有依赖时，被依赖的先问，依赖方留到更晚的轮次。给每个问题编号并附推荐答案，等用户答完一整轮再进入下一轮。

每一轮，用户的回答都会重塑这棵树——已敲定的决策把前沿向外推，解开依赖它们的后续问题。重算前沿前先问一句：“这些答案和探查结果打开了哪些此前未见的子决策？”把新分支挂上树——分支随情况按需扩展，不预设固定的询问框架。

**发出前自检门**：每轮正文发出前过一遍，任一条不过就补齐再发——各问是否达到“用户不追问就能作答”（标准见信息质量节）；选项空间是否穷尽到没有合理的第三选项；新冒出的假设是否都已进盘点台账；本轮回答打开的新分支是否都已挂上树。

## 开局盘点与主题图

开始盘问的首轮，在正文交出三张清单的**初版**——当时所知多少交多少，此后每轮滚动更新：

1. **已知事实**：已查明的信息，逐条附来源（文件路径、命令输出、链接）。
2. **未决未知**：影响决策而尚未查明的信息，逐项配一个探查动作；活账本，中途随时入账，收尾清零。
3. **隐含假设**：一切“我默认 X 成立”——默认值、惯例、常识；逐条升格为新问题，或作为前提显式写进相关问题背景、随该问题一并确认（有独立取舍的必须单独成问）。

**负结果必须报告**：查了没找到的，写明渠道与结果——静默略过会让缺口不可见。

首轮同时附一张**临时主题图**：当前已识别的主题方向，只列标题；它是生长中的草图而非范围承诺，随轮次增删，用户当场指认缺失方向就挂上树。

形式按任务规模缩放（小任务主题图可只有两三个方向、三清单可合并展示），任何一类都不许省略。

## 信息与决策分工

查**信息**是你的职责，绝不是用户的。这里的“信息”泛指一切需要获取的内容——既包括环境中的事实，也包括外部知识。当前沿问题需要这类信息时，自己去查清楚（按环境能力选用工具、子代理或并行探查）——凡是能自己查到的，都别去问用户。不要卡在它上面：一次进行中的探查是一个未敲定的前置条件，因此只有它下游的问题才要等探查完成——本轮先问前沿中不依赖探查的问题，依赖信息的留到探查完成后的下一轮再问。**决策**属于用户——逐条抛给他们，然后等待。

## 优先用结构化提问工具

环境提供结构化提问工具（如 `questionnaire`）时优先用它呈现整轮问题，不可用时回退纯文本。配套约定：

- **正文先行**：调用工具前，正文按上面的格式完整列出本轮全部问题（含每问推荐答案），工具只作点选入口。
- **选项带推荐提示**：选项的 description 里注明推荐标记与理由；工具装不下的展开内容（如三要素全量）以正文为准。

## 示例

```
**问题2** - **解析用现成 crate**：
**背景**：因 问题1 已定 TOML 格式，且手写解析与现成 crate 对用户可感知的结果无差别，故解析实现直接用现成 crate（由 问题1 推得）。
- **A 用现成 crate**：省实现成本；生态成熟、边界处理齐全；代价是引入依赖
- **B 手写解析器**：零依赖、可控；代价是实现与维护成本
**推荐答案**：推荐 A：结果无差别时，依赖成本低于实现成本。

**问题3** - **配置文件放哪里**：
**背景**：目标平台 Linux；工具会在 systemd 用户服务下被调用。
- **A ~/.config/tool/config.toml**：遵循 XDG 规范；systemd 与 chezmoi 等生态按 XDG 路径找配置；代价是路径较深
**推荐答案**：推荐 A：生态兼容是硬需求；放弃的“单文件直白”可由 config 子命令补回。
```

**覆盖度机制正反对照**：

| 机制 | 不合格 | 合格 |
|---|---|---|
| 盘点 | 跳过清单直接抛 问题1 问配置格式，“用户已有现成 schema 文件”这类只有用户知道的信息没机会浮出 | 首轮交初版三清单加临时主题图 |
| 扩展 | 用户答完部署方式就直接问下一题，答案打开的新分支（配置归属、回退路径）无人认领 | 同轮挂上树，编入下轮前沿 |
| 红队 | 分组清单一贴就请确认 | 借检查维度自攻“两台机器同步此配置路径会冲突吗”，再拿清单当线索问出用户补记的约束，发现真问题升格 问题5 回到盘问 |
| 计划 | 红队过后直接把分组清单再贴一遍请确认 | 单独成轮交分步执行计划，每步引用落实的问题与验证、回退方式，异议点升格为新问题盘问后重发完整计划 |

## 完成与收尾

当前沿为空时会话才结束：探查完成且负结果已报、未决清单清零、下游问题已问、每个分支都已走查，不留被默默假设的东西。前沿为空只能由上述条件推出，“问得差不多了”这种感觉不算数。盘问中冒出想直接动手实施的念头时，先重扫一遍主题图和未决账本，确认没有新分支再进入红队。

### 分组清单

此时停下，把已敲定的决策列成**按领域分组的清单**：一个主题一组，组内问题按编号排：

```
## <领域一>

- **问题1** - <结论>
- **问题2** - <结论>

（其余各组同构）
```

### 红队轮

红队轮不可跳过：此时设计树全貌已在手，把分组清单当攻击目标，逐组至少找出一处反例、风险或被默默假设的前提；找到的立即升格为新问题回到盘问并重算前沿，设计树再次稳定后重列分组清单（以修订后结论为准），一组毛病都挑不出才许进入收尾确认。自攻时可参考下列检查维度找漏，但它们非穷尽——表外的轴同样要查：

| 检查维度 | 要追的问题 |
|---|---|
| 目标与成功标准 | 做成什么样算成功？可验证的判据是什么？ |
| 范围与非目标 | 哪些明确不做？边界画在哪？ |
| 约束 | 技术、资源、时间上有何硬限制？ |
| 失效模式与回退 | 会怎么坏？坏了怎么退？ |
| 兼容性与影响面 | 动了谁？波及哪些下游？ |
| 偏好取舍 | 有无无对错的偏好分歧？ |

自攻零发现时，须对照检查维度逐组写明检查过的角度，写不出的组视同未查。

### 记忆线索

自攻完成后、收尾确认前，把分组清单当记忆线索问用户一句：“对着这份清单，有哪些只有你知道、我查不到的背景或约束？”——具体清单比空泛提问更能唤起补记（越具体的线索越容易唤起对应的记忆），此时线索密度全场最高；用户补记的任何内容立即入树回到盘问。

### 执行计划

红队与记忆线索问句走完、设计树稳定后，单独发一轮执行计划作为最后一轮确认内容——只承载计划与确认，不与任何问题混在同一轮。按实施顺序分步，落实决策引用 问题N 编号（编号仅会话内有效，计划落盘为产物时按产物边界转写为结论本身）；每个已敲定决策都要能在计划中找到归宿，无实施动作的结论显式点名。发出前过自检门：决策覆盖无遗漏、步骤顺序无依赖倒置：

```
**步骤 1 - <标题>**：
- **做什么**：<动作，落到可执行粒度>
- **落实决策**：<兑现的 问题N，引用编号，可附一句落实方式>
- **验证方式**：<怎么客观确认做对了，可机制执行的优先>
- **涉及面与回退**：<动了谁、坏了怎么退>

（其余各步同构）
```

请用户确认执行计划并选择下一步：开始实施 / 对计划提异议 / 调整决策。有异议时把异议点升格为新问题，针对计划继续盘问，补丁打在计划上，修订后重发完整计划再确认。确认前不得行动。
