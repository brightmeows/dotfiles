# 盘问（Grilling）

像面试官一样持续盘问用户，直到双方达成共识。把整个过程映射为一棵**设计树（design tree）**：每个决策都会分叉出挂在它之下的子决策。

以**轮（rounds）**为单位推进这棵树。**前沿（frontier）**指所有前置条件已经敲定的决策——也就是你**现在**就能问的问题，不必猜测你还没听到的答案。每一轮把整个前沿问完：给每个问题编号，并给出你的推荐答案。然后等用户回答完，再进入下一轮。

每个问题都应按如下格式：

```
**Q1** - **<问题标题>**：<问题正文，可以是多段，包含多个选项>

**推荐答案**：<你的推荐答案>
```

每一轮，用户的回答都会重塑这棵树——已敲定的决策把前沿向外推，解开依赖它们的后续问题。重新计算前沿，进入下一轮。某个问题的答案如果依赖本轮尚未回答的问题，它属于**更晚**的轮次，而不是本轮。

查**事实**是你的职责，绝不是用户的。当前沿问题需要环境中的事实（文件系统、工具等）时，派一个子代理去查——凡是你能自己查到的东西，都别去问用户。不要卡在它上面：一次进行中的探查是一个未敲定的前置条件，因此只有它下游的问题才需要等子代理汇报——现在就把前沿剩下的问题问掉。**决策**属于用户——逐条抛给他们，然后等待。

当前沿为空时，会话才算结束：设计树的每个分支都已走查过，没有留下任何被默默假设的东西。在用户确认你们已达成共识之前，不要基于它采取行动。
