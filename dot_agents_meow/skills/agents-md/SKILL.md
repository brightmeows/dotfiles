# AGENTS.md 技能

本技能为 AGENTS.md 的创建与维护提供结构化指导。

---

## 定位

**AGENTS.md** 是面向编码代理的项目说明文件。与 README 职责分离：

- **AGENTS.md**：构建命令、测试指令、代码约定、边界规则——面向代理
- **README**：项目概述、快速开始、贡献指南——面向人

README 不杂代理指令，AGENTS.md 不重复项目介绍。

AGENTS.md 是跨工具开放标准，被 60,000+ 开源仓库采用、25+ 工具原生支持。

---

## 层级与作用域

AGENTS.md 按文件系统层级组织，遵循 4 核心作用域概念：

| 概念 | 含义 |
|---|---|
| **管辖范围** | 每个 AGENTS.md 只影响所在目录及子目录，不影响兄弟目录 |
| **累积** | 子目录继承祖先文件的全部指导，无需重复声明 |
| **优先级** | 就近优先，子目录覆盖祖先的冲突规则 |
| **隐式继承** | 子文件免重复祖先规则——代理视指导为累积的 |

| 层级 | 内容范围 |
|---|---|
| **根 AGENTS.md** | 项目描述、共享工具链、全局边界、代码风格基础 |
| **子目录 AGENTS.md** | 该包领域逻辑、局部技术栈、包内特有命令和约定 |
| **深层 AGENTS.md** | 极端特化规则，覆盖祖先的不适用约束 |

根文件应精简，内容冗余则下沉到子目录。子文件只声明该目录特有内容，祖先已声明的无需重复。

## 创建与维护流程

### 增量迭代法

1. **起步**：20-30 行，仅覆盖最常出错的命令和边界
2. **观察**：用真实任务记录代理反复出错的地方
3. **补充**：将反复出现的问题写入
4. **精简**：代理已能遵循的规则可移除
5. **重复**

**大小参考**：推荐 100-150 行；超过 200 行遵循率显著下降（ETH Zurich 2026：冗余内容推理成本 +23%，成功率 -2%）。

**不写推测性规则**——只有当代理反复犯同一错误才添加。

### 重构

- **审计**：遍历现有指令，标记可由工具链强制或已过时的内容
- **拆分**：按层级将臃肿根文件内容分配到子目录
- **迁移**：将确定性规则移出 AGENTS.md，指向工具配置
- **验证**：改动前后对比，确认代理推理开销未增加

### 写作原则

- **代码示例优先**——一个正反代码示例胜过三段文字描述。
  ```
  // 正确：命名导出，const 优先
  export const formatDate = (date: Date): string => { ... }

  // 错误：默认导出，var 声明
  export default function formatDate(date){ var result; ... }
  ```
- **Toolchain First**——确定性约束（代码风格、类型、构建、测试）归属工具链配置，AGENTS.md 只承载建议性指令（架构判断、工作流偏好）。

  ```
  # 正确——指向工具，不重复规则
  Lint: `pnpm lint`（Biome——见 biome.json）

  # 错误——代替工具写规则
  不要用 var，始终用 const/let，import 顺序按标准库/三方/内部排列...
  ```
- **关键文件路径显式标注**——入口点、基类、配置文件应显式标注路径。
- **@import 引用**——部分工具（如 Claude Code）支持 `@路径/文件名.md` 内联引用外部文件，根文件保持精简，知识按需加载。非 v1.1 标准特性，使用前确认工具兼容性。
- **用肯定指令替代否定**——告诉 LLM“不要做 X”反而强化其 attention（Pink Elephant Problem），应改肯定指令或修复代码库摩擦。

### 内容风格

- **力求精简**：能用一句话说明清楚的绝不用一段话。只写要点，不写推测性信息。
- **重点标注非常规**：主流实践、常见配置等显而易见的内容一笔带过；非常规、反直觉、项目特有的内容重点提及。

### 维护规则

- **像代码一样维护**：架构变更时同步更新，过时指令比没有更糟。
- **写前检查**：遍历锁文件、CI 和现有代码模式再落笔（见写作原则 Toolchain First）。
- **行号引用禁用**：用类型名/函数名/模块名代替。
- **路径验证**：所有路径与命令须真实存在，结构图用 Mermaid。
- **定期审计**：周期性审查后将可被工具链强制的规则迁移出去。

### 常见错误

| 错误 | 详见 |
|---|---|
| 含 README 内容 | 定位 |
| 重复工具链已强制内容 | 写作原则 Toolchain First |
| 自动生成不审校 | 参考文件 auto-gen-warning.md |
| 不同工具各维护一份 | 维护唯一 AGENTS.md，symlink 到各工具入口文件（CLAUDE.md / GEMINI.md 等）|
| 否定指令 | 写作原则“用肯定指令替代否定”|

## 附录：AGENTS.md 内容决策指南

维度定义（越高越该放入）：

| 维度 | 含义 |
|------|------|
| **重要性** | 对代理理解项目的重要程度 |
| **推断难度** | 从项目自身获取的困难程度 |
| **稳定性** | 内容变更频率，越稳定越该放 |
| **特异性** | 项目特有程度，越特有越该放 |
| **可工具化程度** | 一票否决——可被工具链强制的内容不放（见附录 C） |

附录条目的维度评分中，**可工具化程度**仅在与一票否决相关时显式标注（如“可工具化：否决”），其余默认为“低”（不易工具化，故应放入 AGENTS.md）。

### 附录 A：推荐放入的内容

重要性高、推断难度高、特异性强——默认应包含。

#### 项目概述

**维度**：重要性：高，推断难度：高，稳定性：高，特异性：非常高

**内容**：
- **根**：项目一句话描述——做什么、给谁用、架构非标准特征
- **子目录**：该包定位与职责简述

#### 项目/包职责边界

**维度**：重要性：高，推断难度：高，稳定性：非常高，特异性：非常高

**内容**：
- **根**：全仓库的包划分与职责归属
- **子目录**：该包的领域边界与外部依赖职责归属

#### 技术栈

**维度**：重要性：高，推断难度：高，稳定性：高，特异性：高

**内容**：
- **根**：所有子包共享的框架/语言/运行时及版本
- **子目录**：该包独占的库/工具及版本

#### 命令

**维度**：重要性：高，推断难度：非常高，稳定性：高，特异性：高

**内容**：
- **根**：全仓库通用的构建/测试/lint/部署命令，带精确 flag
- **子目录**：包内特有命令（如仅该子包的测试/lint 脚本）

#### 代码风格

**维度**：重要性：高，推断难度：非常高，稳定性：高，特异性：高

**内容**：
- **根**：全仓库代码规范、语言级约定（命名导出/const 优先等）
- **子目录**：该包特有约定（如该模块用同步而非异步）
- **不放**：工具链已强制的内容（linter / formatter / type checker）——指向配置

#### 非显而易见的行为

**维度**：重要性：非常高，推断难度：非常高，稳定性：非常高，特异性：非常高

**内容**：
- **根**：全仓库反直觉设计、易错操作、生成文件标记、框架选型原因等代理无法从代码推断的内容
- **子目录**：该包特有的“坑”

#### 代理行为边界

**维度**：重要性：非常高，推断难度：非常高，稳定性：非常高，特异性：高

**内容**：
- **根**：全仓库 Always/Ask/Never 边界规则
- **子目录**：该包特有约束（如永不直接访问某外部服务）
- **Always Do**：每次提交前自动执行（如运行 `pnpm test`）
- **Ask First**：涉及重大变更时先确认（如修改数据库 schema）
- **Never Do**：绝对禁止的操作（如提交密钥、删除测试、push main）

#### 测试

**维度**：重要性：高，推断难度：非常高，稳定性：中，特异性：中

**内容**：
- **根**：全局测试框架、统一 mock 策略、根级测试命令
- **子目录**：该包特有的测试策略、mock 配置

#### 错误处理约定

**维度**：重要性：高，推断难度：非常高，稳定性：高，特异性：高，可工具化：中（类型系统/linter 可部分强制）

**放入条件**：当类型系统（如 Rust `Result`、TS strict mode）或 linter 未完全覆盖时。工具链已强制的部分只需指向配置。

**内容**：
- **根**：全仓库错误处理策略（如“所有 API 返回 Result，永不抛异常”）
- **子目录**：该包特有的错误处理模式

### 附录 B：可选放入的内容（视项目而定）

依项目复杂度、团队规模、安全要求决定是否包含。每条含放入条件说明。

#### 安全策略

**维度**：重要性：高，推断难度：高，稳定性：高，特异性：中（安全规则跨项目通用，如“永不记录密码”）

**放入条件**：项目涉及用户数据、认证、密钥管理或合规要求。

**内容**：
- **根**：全仓库安全边界（如“永不记录密码、密钥”）
- **子目录**：该包特有安全约束

#### Git 工作流

**维度**：重要性：中，推断难度：中，稳定性：高，特异性：中

**放入条件**：多人协作项目，或有标准化分支/提交规范。

**内容**：
- **根**：分支策略、提交格式、PR 流程
- **子目录**：不声明，继承根文件

**注意**：CI 已强制的内容（如 commitlint）可不写入。

#### 环境要求

**维度**：重要性：中，推断难度：中，稳定性：中，特异性：中

**放入条件**：对运行时版本有严格要求，或用非标准工具链。

**内容**：
- **根**：运行时版本要求（Node 20+、Python 3.11）、必需环境变量
- **子目录**：该包特有的环境依赖

#### 代码评审约定

**维度**：重要性：中，推断难度：非常高，稳定性：高，特异性：中

**放入条件**：团队有明确评审标准，且代理参与 PR 流程。

**内容**：
- **根**：PR 评审要求（如“改动必须附带测试”、“先更新 AGENTS.md”）
- **子目录**：该包特有评审流程

#### 架构说明

**维度**：重要性：中，推断难度：低，稳定性：非常高，特异性：高

**决策依据**：推断难度低（代码结构可见），但特异性高（每个项目不同）。仅非标准布局值得说明。

##### 推荐放入

| 内容 | 理由 | 维度分析 |
|------|------|----------|
| 非标准目录布局说明 | 代理从目录结构无法推断 | 特异性高且推断难度高，放入价值最大 |

#### 数据定义

**维度**：重要性：中，推断难度：低，稳定性：高，特异性：高

**决策依据**：代码自身已表达数据结构定义，仅需补充关键实体间关系。

##### 推荐放入

| 内容 | 理由 | 维度分析 |
|------|------|----------|
| 关键数据模型说明 | 辅助代理理解核心实体间关系 | 特异性高，口头说明比读代码快 |

#### 第三方依赖 / 外部服务

**维度**：重要性：中，推断难度：中，稳定性：低，特异性：中

**决策依据**：稳定性低（变更频繁），仅写入从代码/lockfile 无法推断的信息。

##### 推荐放入

| 内容 | 理由 | 维度分析 |
|------|------|----------|
| 已知兼容性问题 | lockfile 无法体现 | 特异性高且稳定性差，更需文档 |
| 特殊配置说明 | 非标准用法需额外说明 | 推断难度高 |
| 服务 URL（非密钥） | 节省查找时间 | 推断难度中 |

### 附录 C：不应放入的内容

维护成本高、过时风险大、或已有更好的替代位置。

#### API 文档

**维度**：重要性：低，推断难度：非常低，稳定性：低，特异性：低

**不放理由**：函数签名变更频繁，与代码不同步即产生误导。代理可直接读取类型定义和 JSDoc。

**替代方案**：类型注解（TypeScript/Python）配合代码注释，由工具自动生成文档

#### 部署流程

**维度**：重要性：低，推断难度：非常低，稳定性：低，特异性：中

**不放理由**：部署步骤随环境频繁变化，写入 AGENTS.md 后极易过时。

**替代方案**：见 `docs/DEPLOY.md` 或 CI 配置（Dockerfile / CI YAML）

#### 工具链已强制的内容

**不放理由**：linter、formatter、type checker 已自动强制执行，写入属重复劳动。代理优先服从工具输出而非文本指令。

**替代方案**：在 AGENTS.md 中仅注明“见 biome.json / tsconfig.json”等指向性说明。

#### 架构说明

| 不放内容 | 理由 | 替代方案 |
|----------|------|----------|
| 长篇架构概述 | 变更频繁，与代码不同步，维护成本高 | 见 `docs/ARCHITECTURE.md` |
| 组件关系图/数据流图 | 图表维护成本高 | 见 `docs/ARCHITECTURE.md`（Mermaid） |

#### 数据定义

| 不放内容 | 理由 | 替代方案 |
|----------|------|----------|
| 完整数据库 schema | 代码即真相源，变更同步成本高 | 见 ORM 实体定义或 `docs/DATABASE.md` |
| 详细字段类型定义 | 代码即文档，类型注解已覆盖 | 见 类型定义代码 |

#### 第三方依赖 / 外部服务

| 不放内容 | 理由 | 替代方案 |
|----------|------|----------|
| SDK 完整用法文档 | 官方文档更准确 | 见 外部文档链接 |
| 密钥/Token 值 | 安全风险 | 改用环境变量或密钥管理服务 |
