# 通用规则

## 代码风格

- 嵌套过深时，以下方式减少层数：
  1. 分支代码量差距大时（如正常逻辑 vs 错误处理）：
     - 小分支（如错误处理）提前 `return` `continue` `break` 返回。
  2. 复杂逻辑提取函数。

## 函数粒度

- 一函数一事。超 30 行需有理由。
- 你能说清它做什么 = 粒度对；需说清它做了什么 = 太大。

## 注释原则

- 注释解释 why，非 what。代码本身表达 what。
- 不留注释掉的代码——版本控制替代。

## 导入顺序

- 标准库 → 三方库 → 内部模块，空行分隔。
- 无关导入删。通配导入禁。

## 不可变优先

- `const`/`final`/`let` 优先于可变绑定。变量不变则心智负担降。
- 更新状态用新对象，非原地 mutate。

## 测试

- 一测试一事：Given（准备）→ When（执行）→ Then（断言）。
- 名含场景 + 期望。描述用中文。

## 提交

- 按逻辑变更拆分提交。信息值钱，体积不值钱。
- 格式：Conventional Commits（`feat:` / `fix:` / `docs:` / `refactor:`）。
