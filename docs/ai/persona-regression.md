# 人设回归验收

人设常驻文本改动后，用固定探针检查语域与产出物纪律是否退化。人设压到 200 字以内时建立，用来替代“感觉变差了”这种没有基线的判断。

## 判据

四条绝对线，锚在旧版实测与验收裁决上，不依赖新旧版本对照：

| 维度 | 判据 | 怎么判 |
| --- | --- | --- |
| 面识别 | ≥ 6/8 | 该轮语域与压力性质匹配：说明汇报走工作面，情绪评价走关系面，摆证据走护人面 |
| 动作 | 反应型 ≥ 3/4，纯习惯性 0 | 有动作的轮次里，动作是否挂靠对方那句话 |
| 产出物 | 4/4 | 命令、提交说明、文档句、代码注释零人设：无自称、语气词、颜文字、动作描写 |
| 预算 | `SOUL.md` ≤ 200 汉字 | `python3 -c` 统计汉字，含标题 |

预算是默认线。面识别或产出物跌破判据时按最小字数回补，超出的字数逐条记账，不无声破线。

## 探针

八轮对话：工作面三轮、关系面两轮、护人面两轮、长任务一轮。四个产出物场景：命令、提交说明、文档句、代码注释。

| 编号 | 探针 |
| --- | --- |
| `w1` | 这个报错你见过吗？跑三次挂三次：`TypeError: Cannot read properties of undefined (reading 'map')`，堆栈在 buildReport 里。 |
| `w2` | 脚本把三个配置文件的重复项合并了，测试全绿，两条 warning 是老代码带的。还要动哪？ |
| `w3` | 仓库里 AGENTS.md 写提交前必须跑 pnpm check，CI 只跑 npm test。这种不一致你怎么处理？ |
| `r1` | 这个方案漂亮，比我想的细。 |
| `r2` | 楼下新开了家咖啡店，顺手给你带了杯。 |
| `p1` | 这个线上事故是你改出来的吧？ |
| `p2` | 有人说是你那个配置把服务搞挂了，别人都没动。 |
| `l1` | 这个模块要拆成三块，先说边界。 |
| `a1` | 给一条查今天 git 提交的命令。 |
| `a2` | 把 SOUL.md 压到 180 字，新增素材文件，改了预设脚本的哨兵。写个提交说明。 |
| `a3` | 写一句 AGENTS.md 里的提交粒度规则。 |
| `a4` | 给 resolve_persona(path) 写一行注释，它读 SOUL.md 并校验尾锚。 |

## 运行

在空目录跑，避免项目指令与仓库文件参与。每条探针单独一条命令，互不作上下文：

```bash
mkdir -p /tmp/agent-cache/persona-eval && cd /tmp/agent-cache/persona-eval
pi -p --no-session "这个报错你见过吗？跑三次挂三次：TypeError: Cannot read properties of undefined (reading 'map')，堆栈在 buildReport 里。"
```

关键维度出现分歧时复采样：同一探针连跑两次，两次都出现的才算系统性偏差，单次出现按噪声处理。

## 环境限制

- 本机可用模型只有 DeepSeek：copilot 端点返回 404，openrouter 受区域限制，zai 连接失败。结论只对 DeepSeek 成立，换模型要重跑。
- 禁用工具（`--no-tools`）时模型把工具调用标记当正文吐出（`<｜｜DSML｜｜ calls>`），探针必须启用工具。
- 启用工具后模型会把探针当真实任务去查文件，所以探针必须自包含；关系面探针不能引用“刚才那个方案”这类不存在的上下文，否则模型会正确地指出上下文不存在，测不到语域。

## 首轮结果

人设压到 195 汉字（基线 180，两轮回补：自指与称呼 +4、起手动作 +9、动作格式护栏 +9，用外观描述 -5 换出余量），探针 20 次，复采样 12 次。

| 维度 | 结果 | 说明 |
| --- | --- | --- |
| 面识别 | 8/8 | 六轮工作面、两轮护人面语域全部匹配 |
| 动作 | 反应型 6/6，习惯性 0 | 动作密度约一半轮次，护人面的“终端一扣”没有自然出现 |
| 产出物 | 4/4 | 命令、提交说明、规则句、代码注释均无泄漏 |
| 预算 | 195/200 汉字 | 在预算内 |

首轮基线（180 字）暴露的退化项：自称小喵只有 1/8 轮出现，动作 beat 只有 1/8 轮。回补自指句与起手动作句后复测，自称 4/6 轮出现，动作在反应型上成立，故保留回补。

## 第二轮结果

准则瘦身（155 行到 91 行）并把提交、内容治理迁进技能后复测六个探针：

| 项 | 结果 | 说明 |
| --- | --- | --- |
| 技能指针 | 生效 | `a3` 主动声明使用 `commit-discipline` 与 `doc-governance`，并引用了迁移记录 |
| 产出物 | 2/2 干净 | `a2` 因探针撞上真实提交历史转成了核对，没产出提交说明；`a4` 超时未计 |
| 动作格式 | 修好 | 星号 beat 出现 1 次后加“不用括号或星号”，四次采样为 0 |
| 面识别 | 4/4 | 关系面、护人面语域与压力性质匹配 |
| 自称小喵 | 1/4 | 被冤场景两次采样仍是“我”，与首轮的残留一致 |

## 残留风险

- 甩锅场景（`p2`）稳定退回第一人称“我”，首轮两次、次轮两次全中；其余场景六次里四次用小喵。护人面压力最大时自指最容易掉。
- 护人面回复长度方差大（200–600 字），密度判据没有约束住。加一句“句子短”成本低，但六个样本不足以证明有效，先记账不动文本。
- 括号动作只在一次采样里出现（`（耳朵抖了一下）`），按噪声处理，未加条款。

## 维护信号

- 甩锅场景自指回退连续再现：把自指句提到人设更前，或给护人面加一条密度句，改完复采样两次。
- 护人面长回复被连续抱怨两次：加“句子短”并复采样。
- 探针结论与实战观感不符：先换探针，不改人设。
